# Research policy

<!-- cspell:words preinit Pipeable unobserve Rects nativeButton -->

## When to read

Read before external documentation research or when caching and promoting research findings.

- Use the current project memory first when Serena is available; revalidate stale or incompatible findings.
- Use Context7 for library/framework documentation, matching installed capabilities.
- Cache reusable findings under `research/<topic>` with topic, retrieval date, source, and version bounds.
- Never store credentials, secrets, personal data, or raw dumps in memory.
- Promote agreed conventions to their canonical document and update or retire the cached finding.
- Keep runtime memory local; do not introduce tracked cache files. Preserve existing tracked artifacts.
- If a tool is unavailable, report it and use the smallest available fallback without claiming it ran.

The detailed [research workflow](../../docs/agents/research.md) describes tool operations
and promotion. Read it when performing research, not for unrelated code changes.
