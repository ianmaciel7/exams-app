# Release v0.1.0

## Scope reset — 2026-11-26

The product owner requested a fresh v0.1.0 release definition. **No feature is currently selected for the new scope.** Previous approvals, design baselines, and boards are preserved as historical evidence, not active release requirements. Review candidates in the [Ideas Board](https://github.com/ianmaciel7/exams-app/tree/dev/docs/boards/overview); only explicitly selected ideas enter the new release. Keep the version number v0.1.0. No prior implementation or validation status is transferred automatically.

This index locates the current planning artifacts. A documented baseline is not a tested or implemented product. Activities can be revisited and do not form mandatory waterfall gates.

| Historical artifact | Previous purpose and source | Historical progress | Historical validation |
| --- | --- | --- | --- |
| [Product](product/) | Discovery board; [release decisions and history](product/product.md) are the source of truth, with root `PRODUCT.md` for evolving context | Baseline documented | User validation pending |
| [Information Architecture](information-architecture/) | Destinations, organization and navigation | Baseline documented | Usability validation pending |
| [Screen Inventory](screen-inventory/) | Screens, surfaces and states | Baseline documented | Usability validation pending |
| [User Flows](user-flows/) | Study paths and decision branches | Baseline documented | Usability validation pending |
| [Sketch](sketch/) | Exploratory workspace composition, essential state sketches and brief design annotations | In progress | Previous native capture passed; corrected rail capture and user review pending |

Low-, mid- and high-fidelity wireframes, mockups and interactive prototypes have not started. Choose the fidelity needed to answer the question; optionality is separate from progress. Runnable prototypes belong in `prototypes/`.

Progress values: **Not started**, **In progress**, **Baseline documented**, and **Completed**. Validation is recorded separately as **Pending**, **In progress**, **Passed**, or **Not applicable**, with evidence for any claim of success. Keep stage cards, board links, this index and the release decision record aligned when work changes.

Release board titles use `<Artifact Name> — v<release>`; directory names remain lowercase kebab-case. Artifact iterations use Git history unless versions must coexist. Historical wording and original references are preserved.

The previous stage records contain historical navigation proposals, including superseded variants. None is assigned to the reset scope. The Questions toolbar (filters, Auto-check, sorting, result count, questions per page, and List/One) and per-question Statistics are unprioritized ideas with no release assignment. The previous Sketch revision was visually captured. Native capture and usability validation remain pending for the historical revision. All activities are not started for the newly reset scope.
