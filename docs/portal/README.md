# Native artifact Playground

The Playground is the only public interface. The GitHub Pages root redirects to `playground/`. The native preview uses the upstream Open Artifact Playground v0.17.0, pinned to commit `0f6079853c8b0d2f4e9bddf5465ddbda722ce5a9`. See [upstream deployment documentation](https://github.com/JimLiu/open-artifact/blob/v0.17.0/website/README.md#deploy).

The Pages workflow captures board evidence and authentic thumbnails first using the existing v0.16.3 runtime; the former screenshot viewer is retained only as source history, not deployed as a second interface. The isolated native build reads the same committed board snapshot, uses the upstream Shell and whiteboard editor, and tests the exact persisted element IDs for all eleven boards at a repository subpath before making the preview available. No original board, state screenshot, or plugin installation is migrated. The native build is required: if validation fails, no new Pages deployment is made; the previous successful deployment remains available. The downloadable board evidence is kept in Actions.

The deployment environment remains `github-pages` (the existing Pages configuration). The root entry and direct `playground/` URL lead to the same library. Its home follows the upstream native artifact library (semantic theme tokens, 12 px card grid, authentic 16:9 thumbnails and compact metadata), groups project boards separately from the release's product/structure and interface-design stages, and links directly to the interactive native editor. The order, numbering, status and current-stage shortcut are derived from the committed release state, not inferred from board element counts. The Grid/List switch persists the display preference in the browser; both views keep the same order. Unstarted stages remain documented in Release Stages rather than being shown as unavailable artifact links. The build checks all home cards, thumbnail decoding, keyboard navigation, canonical stage sequence, current-stage shortcut, Grid/List switching and preference persistence, and horizontal overflow at desktop and mobile sizes in the tested themes. The static template lives in `docs/portal/playground-home.html`. Edits and new comments in this preview are temporary browser-memory changes, not synchronized to GitHub. The simulated agent is disabled. The editor uses its native Shell header with a back-to-library link and a neutral temporary-edits indicator; the upstream website demo banner and its language/dismiss controls are removed. The build checks these controls on every board and the mobile keyboard return path. Private/local runtime comments and history are deliberately excluded. Native rendering may differ from the project-specific v0.16.3 screenshot styling; visual parity, existing anchored comment display, and full mobile interaction coverage remain separate review gates. The owner requested the Playground as the only public interface; that decision does not establish those QA results.

## Publication inventory and exploratory studies

The committed design roots are classified independently of the eleven whiteboards. Identity, workspace visual design and motion studies are provisional. The pinned upstream native editors are seeded from the same committed source as the boards, with immutable GitHub source links retained. The build writes `playground/publication-inventory.json` and rejects new or missing design directories until explicitly classified. Browser checks require the same preview and source links in Grid and List at desktop/mobile widths, exact eligible seed path coverage, loaded store entries (DB document keys normalized separately from project-file paths), the correct native editor and representative rendered text. The capture evidence is uploaded before Playground verification so a later editor failure does not discard review evidence. These checks do not establish per-artboard visual parity, runtime accessibility, or owner approval. Actual served-page verification and per-section visual review remain separate acceptance gates (#17, #20).

Rollback: revert the single-public-interface commit if required. The old screenshot viewer source and evidence remain intact. Do not delete historical deployments or change environment protections.
