# Capacities: organização do produto

Como o produto organiza o conhecimento. Marcações: **Confirmado** (página pública) ou **Inferência**.

## Princípio central
- **Confirmado** (/product, home): "In Capacities, you don't create files—you create objects." O conteúdo é organizado por **coisas** (pessoas, livros, projetos, ideias), não por pasta. Crítica explícita a "Files & Folders" (home, comparação "Messy, deep, lost" versus "Clear, connected, alive").

## Hierarquia de conceitos
| Conceito | Papel | Confirmado em |
|---|---|---|
| Espaço (space) | Contêiner do conteúdo do usuário; "Unlimited spaces" no Basic | /pricing |
| Objeto | Unidade de conhecimento com tipo e propriedades | /product |
| Tipo de objeto | Modelo com propriedades e template; criado sob demanda | docs Object types |
| Propriedade | Campo tipado (data, número, tag, link, caixa) | /product |
| Bloco | Parte do conteúdo dentro de uma nota (texto, lista, código) | /product, Editor |
| Link / backlink | Conexão bidirecional entre objetos | /product |
| Daily note | Nota diária, ponto de entrada | /product |
| Área (Area) | Tipo pronto para agrupar trabalho e vida por responsabilidade | docs Object types |
| Consulta (query) | Filtro salvo sobre objetos (Pro) | /pricing |
| Quadro (whiteboard) | Visão espacial de objetos (Pro) | /product |
| Tarefa | Ação com data, ligada à origem (Pro) | /product |

## Tipos prontos (docs, Object type reference)
Agrupamento por finalidade, feito por mim a partir das descrições oficiais:
- **Pessoas e organizações**: Person, Organization.
- **Trabalho e tempo**: Project, Meeting, Area, Day, Week, Month.
- **Conteúdo de consumo**: Book, Film, TV series, Podcast.
- **Conhecimento**: Atomic note, Definition.

## Como o produto evita pastas (Confirmado)
- Tipos são criados conforme a necessidade ("Create the object types you need as you go", home).
- Tags são globais, não presas a uma base (/product).
- Busca e consulta substituem a navegação por pasta.

## Mapeamento para o Exams App (Inferência)
Hierarquia de conteúdo proposta, em forma de tipos de objeto:
- **Concurso / Certificação** (equivale a Project ou Area)
- **Edital / Disciplina** (equivale a Area)
- **Tópico** (equivale a Atomic note)
- **Questão** (equivale a Definition, com propriedades: alternativa correta, banca, ano, taxa de acerto)
- **Simulado** (equivale a Meeting, com data, duração e resultado)
- **Leitura / PDF** (equivale a Book com grifos)
- **Dia de estudo** (equivale a Day)

Riscos observados:
- Excesso de tipos confunde (o próprio produto recomenda criar tipos "conforme necessário"). Começar com poucos tipos.
- Sem pastas, o aluno pode perder a visão de trilha. Por isso a navegação por edital precisa existir como visão própria, não só por busca.
